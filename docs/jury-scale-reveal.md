# Jury "scale countdown" reveal (JESC 2024 format)

An opt-in alternative presentation of **jury** voting, modelled on Junior
Eurovision 2024. Off by default; enabled with **Settings → Voting → "Scale
countdown jury reveal"** (`settings.enableJuryScaleReveal`).

1. **Scale phase** — the board reveals *every* 1 point awarded by *every* jury at
   once, then every 2, and so on up to the last non-douze value. Countries that
   scored show the amount received in that step plus the flags of the juries that
   awarded it; that overlay clears after `ANIMATION_DURATION` (3s), or stays until
   the next set replaces it with `settings.keepJuryScaleRevealAwards`.
2. **Douze phase** — spokespersons appear one at a time, each announcing their 12.
   Here the overlay **persists for the whole phase** and **accumulates** (five 12s
   → `60`), and only the country the latest spokesperson picked shows a flag.
3. **Finish beat** (`phase: 'awaitingFinish'`) — after the last award the stage is
   deliberately *not* committed. The board holds with the final douze on screen
   behind a single "Continue to televote" / "Show results" button. Without it the
   televote board or the results modal replaced the reveal the instant the last 12
   landed, so nobody could see where it went.

Televoting is untouched, and so is the default scoreboard. This is a second
*view* of the same votes, not a change to the voting engine.

## Why it is only a view

`predefinedVotes[stageId].jury` (or `.combined`) is a **complete**
`voterCode → Vote[]` matrix before a stage starts — generated by the
Plackett–Luce engine via `predefineVotesForStage`
([predefinitionActions.ts](../src/state/scoreboard/predefinitionActions.ts)) or
authored in the predefinition modal. Every `Vote` carries `pointsId`, so "all the
1 points" is a group-by over data that already exists.

The whole reveal is therefore a function of a 3-value cursor:

```
(phase, stepIndex, votingCountryIndex) × predefinedVotes → what's on screen
```

Nothing derived is stored — the award overlay is recomputed on every render — so
it cannot drift from the points on the board. Final per-country jury totals are
identical to the default flow by construction, which is what lets qualification,
tiebreaking, the stats breakdown, leaderboard snapshots and contest saving keep
working with no changes. `juryScaleReveal.test.ts` asserts exactly this: a full
replay of every step and every spokesperson equals the matrix column sums.

## State

```ts
juryScaleReveal: { stageId, phase: 'scale' | 'douze' | 'done', stepIndex } | null
juryScaleRevealAwardsHidden: boolean            // transient
juryScaleRevealHideTimerId: NodeJS.Timeout | null // transient
```

**`votingCountryIndex` is reused as the spokesperson cursor** during the douze
phase, so it means exactly what it does in the default flow. `getVotingCountry()`,
`CountryInfo` and the jury progress bar work unchanged, and the hand-off to
televote reuses the existing index arithmetic.

Two things that are easy to get wrong and are load-bearing, both in
[scoreboardStore.ts](../src/state/scoreboardStore.ts):

- `juryScaleReveal` is in the **persist** `partialize`. Without it a refresh
  mid-countdown restores the awarded points but resets the cursor to step 0, and
  every step gets awarded a second time.
- `juryScaleReveal` is in the **zundo (`temporal`)** `partialize`, so the undo
  button in `SimulationHeader` rolls the cursor back together with the points.
- `juryScaleRevealAwardsHidden` is deliberately a *separate* field excluded from
  both. Inside the cursor object, the hide timer firing would push a junk
  past-state that "undo" would consume instead of undoing a step.

The cursor self-initialises: `resolveJuryScaleRevealCursor` returns a fresh
`{ phase: 'scale', stepIndex: 0 }` whenever the stored slice belongs to another
stage, so stage transitions need no setup. It is cleared in `startEvent` (which
also covers Restart), `leaveEvent`, and `applyContestSnapshotToStores`.

**Stage ids are not unique across contests.** They are the constants `SF1`, `SF2`
and `GF`, so a *persisted* cursor from one contest matches the same-named stage of
the next one on id alone. That caused a real bug: loading a saved contest in
presentation mode goes through `applyContestSnapshotToStores`, which pushes state
with `useScoreboardStore.setState` and never calls `startEvent` — so the previous
run's `phase: 'done'` cursor survived, the countdown was skipped entirely, and
every country ended up with only `12 × (number of 12s received)`.

Fixed on both levels, and both are worth keeping:

- that restore path now calls `resetJuryScaleReveal()` (which also cancels a
  pending hide timer);
- `resolveJuryScaleRevealCursor` no longer trusts id equality alone. A cursor
  claiming progress (`phase !== 'scale'` or `stepIndex > 0`) against a stage with
  no jury points on the board has to be stale, so it is discarded. Any future code
  path that sets up a simulation without going through `startEvent` is covered by
  this on its own.

## The step machine

```
steps = pointsSystem.filter(!showDouzePoints), ascending by value then id
douze = pointsSystem.filter(showDouzePoints)

scale, stepIndex < steps.length:
    apply every vote with pointsId === steps[stepIndex].id
    stepIndex++              ← phase stays 'scale' even on the last step, so that
                               overlay survives; the switch happens on the next
                               advance, which awards in the same call
    no douze items at all → finish jury voting here
otherwise (the spokespersons are up):
    apply voters[votingCountryIndex]'s douze-tier votes, summed per recipient
    votingCountryIndex++
    last voter → phase 'awaitingFinish'

awaitingFinish:
    commit the stage (the button, the `f` hotkey and the presentation loop all
    land here; the loop's `pauseAfterAnimatedPoints` delay is what gives the beat
    its length during auto-presentation)
```

"Finish randomly" also stops on the beat rather than committing outright —
skipping ahead should not bury the 12s either.

`finishJuryVoting` copies the tail that already appears three times in
`votingActions.ts`: `handleStageEnd` + `isOver` for `JURY_ONLY`/`COMBINED`,
otherwise `isJuryVoting: false` and the televote start index. It was copied rather
than extracted so this feature cannot change the default flow's behaviour. It also
sets `isLastSimulationAnimationFinished: true` — the normal board flips that flag
from `handleBoardTeleportAnimationComplete`, which this board never runs.

**Theme sounds** are fired from the actions. `playThemeSound('douzePoints')`
normally comes from inside `DouzePointsAnimation`, which this board never renders,
so it would otherwise be silently lost.

### Edge cases

| Case | Behaviour |
| --- | --- |
| Several `showDouzePoints` items | All belong to the spokesperson phase; a voter awards all of theirs at once |
| A flagged item is not the highest value | Still the spokesperson phase — the flag means "announced", not "highest" |
| No flagged items | No spokesperson phase; the countdown ends jury voting |
| All items flagged | The countdown is empty; the first advance goes straight to spokespersons |
| Duplicate values in the points system | One step per item — grouping is by `pointsId`, never by value |
| `allowMultiplePointsToSameEntry` | Handled by the group-by |
| `COMBINED` stage | Reads `.combined` instead of `.jury`, as `giveJuryPoints` does |
| Voters absent from the matrix (e.g. televote-only WW, or a voter set to "Televote only") | Skipped — awards iterate `getStageVotingCountries(…, { channel: 'jury' })`, not matrix keys |
| Setting switched on mid-stage | `isJuryScaleRevealActive` refuses to take over once the default flow has put jury points on the board, so points are never re-awarded |

## When the board is on screen

`isJuryScaleRevealActive` is the single source of truth, used both by
`Simulation.tsx` (to render) and by `PresentationPanel` (to decide which flow
advances). It requires the setting on, a non-televote-only stage, not a
pick-qualifiers semi-final, and either an in-progress jury phase or a *jury-terminal*
stage (`JURY_ONLY`/`COMBINED`) that this reveal finished — that voting-mode guard
is what stops the bars reappearing after televote ends a `JURY_AND_TELEVOTE`
stage. It also bows out for `showAllParticipants` and the finished-event stage
picker, which show data this single-stage board cannot represent.

Consequence: a `JURY_AND_TELEVOTE` stage flips back to the normal sorted
scoreboard the moment the jury finishes, and a `JURY_ONLY` stage keeps the bars up
under the winner modal until the user continues.

## Layout

Fixed order (`stage.runningOrder`, else stage order) with **no sorting and no
re-ordering** — which is why none of the board's `Flipper`/FLIP/GSAP machinery is
involved. Column, top to bottom: jury flags (capped at 4 + "+N", overlapped so a
full stack fits the reserved height), the received-points bubble, the bar with the
name rotated inside it, the participant flag, the running total.

The overlay area has a **reserved height** so revealing an award never shifts the
bars. Columns are `flex: 1 1 0` with a `--reveal-col-min` floor, so a small field
fills the width and a large one scrolls; after each advance the board
`scrollIntoView`s the top-scoring new recipient, without which most reveals happen
off-screen on a phone.

### Colours

All from existing `countryItem` theme tokens — the feature adds none:

| Element | Token |
| --- | --- |
| Bar fill (resting) and, dimmed over a dark scrim, the unfilled part | `juryBg` |
| Bar fill + bubble when the country just scored | `juryLastPointsBg` / `-juryLastPointsText` |
| Name | `juryCountryText`, or `juryLastPointsText` while highlighted |
| Running total | `juryPointsBg` / `-juryPointsText` |
| Current-leader ring | `televoteOutline` |

### Qualifier readout

On a jury-only / combined **semi-final** the bars stay up after the stage is
decided, and there is no sorted scoreboard to read the cut-off from — so once
`stage.isOver` and the stage has `qualifiesTo` targets, the fill switches meaning:
qualifiers take the `juryLastPointsBg` highlight and non-qualifiers are dimmed to
40%. `RevealColumn` gives this precedence over the "just scored" colour, since by
then no award is in progress.

Two traps worth remembering:

- The unfilled part of the track is `juryBg` at reduced **opacity** over a scrim,
  not a colour of its own. Several themes give `juryBg` and `juryPointsBg` the
  same value, and the name needs the contrast the theme designed for it whatever
  the fill height is.
- tw-colors exposes theme colours as `--twc-…` variables holding **bare HSL
  channels** (`0 0% 100%`), so they cannot be dropped into a `box-shadow` value.
  The leader ring uses the `ring-2 ring-inset ring-countryItem-televoteOutline`
  utilities instead. (`CountryPlaceNumber.tsx` has a latent
  `color: var(--countryItem-…)` that silently does nothing for the same reason.)

## Not implemented (deliberate)

**Click-to-award.** In the scale phase there is no single choice to make. In the
douze phase there is, but the override swap in
[`giveJuryPoints`](../src/state/scoreboard/votingActions.ts) also moves the clicked
country's *other* vote from that voter when duplicates are disallowed — in this
mode that is a lower-points vote already applied to the board, so reusing it would
desync the board from the saved matrix and corrupt the stats breakdown. A correct
version swaps only the douze-tier vote and reconciles both countries' applied
points. Nothing in this design blocks adding it.

Also outstanding: a count-up on the totals, richer step transitions, and a compact
mobile layout (horizontal bars in a vertical list) mirroring the existing
`scoreboardMobileLayout` toggle.
